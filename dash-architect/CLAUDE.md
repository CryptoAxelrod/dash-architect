# CLAUDE.md — правила проекта Dash Architect

Эти правила обязательны для всего кода в репозитории. Они важнее любых локальных удобств,
привычных паттернов или желания добавить "просто одну маленькую зависимость". Если задача
кажется нерешаемой без нарушения одного из пунктов — сначала спросить пользователя, а не
нарушать правило молча.

## 1. Детерминизм — это инвариант, а не настройка

- Генерация дашборда — чистая функция от (а) сырых данных таблицы и (б) явной конфигурации
  маппинга столбцов. Один и тот же вход обязан всегда давать один и тот же дашборд —
  побайтово идентичный выход структуры данных.
- **Никаких обращений к LLM.** Ни в рантайме, ни за флагом, ни как "необязательное улучшение".
  Ни один путь кода не может зависеть от ответа модели, чтобы построить дашборд.
- Никакой скрытой недетерминированности в путях, определяющих структуру дашборда:
  `Math.random`, `Date.now()`, порядок обхода `Map`/`Set`, если он влияет на результат,
  системная локаль/часовой пояс окружения — всё это либо запрещено, либо должно быть явно
  зафиксировано входными данными (например, "текущая дата" — только если она передана как
  параметр, а не считана из окружения во время генерации).

## 2. `/engine` — чистый Node-модуль, ничего не знающий про Excel

- Ноль упоминаний Office.js, Excel API и DOM API в `/engine` — ни в виде импортов, ни в виде
  фактических вызовов. Никаких `window`, `document`, `Excel.run`, `Office.context`.
- `/engine` обязан запускаться в чистом Node (`node script.js`) без браузера и без каких-либо
  Excel/Office шимов.
- Вход `/engine`: массив массивов (сырые значения ячеек) + метаданные форматов (number format
  строки, по колонкам и/или по ячейкам). Выход: JSON-совместимая структура данных, описывающая
  дашборд.
- `/engine` не производит HTML, SVG-разметку или DOM-узлы и не знает, как его вывод будет
  отрисован — ни в интерактивном виде, ни в статичной картинке. Это забота `/render`.

## 3. Ноль сетевых вызовов

- `/engine` и `/addin` никогда не делают сетевых запросов: ни к LLM, ни к геокодерам, ни к
  курсам валют, ни к аналитике, ни к CDN во время выполнения. Всё нужное приходит на вход или
  зашито в билд заранее.

## 4. Зависимости — по умолчанию ноль, любое добавление обсуждается

- `/engine`: ноль внешних npm-зависимостей. Разбор дат, чисел, локалей (включая случаи вроде
  `07.04.2024`, `925 408,28`, `48,5%`) реализуется вручную.
- `/addin`: ноль сетевых вызовов (см. п. 3). Office.js — часть хостовой среды Excel, а не
  npm-зависимость проекта.
- `/render`: зависимости допустимы только если задача принципиально нерешаема без них.
  **Перед добавлением любой зависимости в `/render` — спросить пользователя и получить явное
  согласие**, даже если она кажется маленькой или dev-only.

## 5. Никаких графических библиотек — только SVG руками

- Никаких Chart.js, D3, Recharts, ApexCharts, Highcharts и аналогов — нигде в проекте.
- Все графики — SVG-разметка, собираемая вручную кодом рендер-слоя из данных, отданных
  `/engine`.
- Причина зафиксирована как архитектурное требование: один и тот же рендер-код должен уметь
  выдать и живой интерактивный DOM (для аддина в Excel), и статичную картинку (для экспорта/
  превью/скриншота). Сторонняя chart-библиотека с собственным canvas- или DOM-рантаймом это
  требование нарушает.

## 6. Изменение правил классификации столбцов = обновление снапшотов

- Любое изменение правил определения роли столбца в `/engine` обязано сопровождаться
  обновлением снапшот-тестов в `/tests` в том же коммите/PR.
- Снапшоты фиксируют результат классификатора на фикстурах из `/fixtures`. Если правило меняет
  классификацию хотя бы одной колонки хотя бы в одной фикстуре — это обязано явно отразиться в
  обновлённом снапшоте, а не быть скрыто отключённым или пропущенным тестом.

## 7. Пользовательская правка маппинга непобедима

- Если человек вручную переопределил роль столбца на экране маппинга, это решение — источник
  истины. Оно не пересматривается автоматикой при перегенерации дашборда.
- Автоматическая классификация запускается только для столбцов, у которых нет сохранённого
  пользовательского решения.
- При перегенерации (обновление данных, повторный запуск и т.п.) сохранённые пользовательские
  правки применяются, а автоматические правила заполняют лишь то, что осталось. Хранилище этих
  правок не может быть эфemерным и не может очищаться логикой автоматической классификации.

## Структура репозитория

- `/engine` — детерминированная логика: разбор таблицы, классификация столбцов, построение
  структуры дашборда. Чистый Node, без внешних зависимостей.
- `/addin` — код Excel-надстройки (task pane + content add-in), интеграция с Office.js.
- `/render` — превращение структуры данных из `/engine` в интерактивный DOM и в статичный
  экспорт (SVG-графики вручную, без сторонних chart-библиотек).
- `/fixtures` — тестовые таблицы (CSV/XLSX), покрывающие разные форматы и ловушки данных.
- `/tests` — снапшот-тесты и прочие проверки, в первую очередь для правил классификации
  столбцов из `/engine`.
- `/reference` — нерабочий демо-макет (референс интерфейса и визуального языка), не часть
  продукта, не импортируется кодом.
